# QuickStart direct-queue regression checklist

Source: `e2e/quickstart.spec.ts` has 13 named tests plus 4 generated axe cases (dark/light × 390/1440 px). Adapt the expectations below while keeping the shared API mocks and file fixtures where they still fit. The queue should stay on `/`; there is no longer a separate “Was soll passieren?” view or tool-choice phase.

| # | Existing QuickStart test | Direct-queue expectation |
|---:|---|---|
| 1 | Auswahl zeigt Titel, eine Dropzone und höchstens eine Textlinkliste statt Karten | Keep the empty state title, picker, dropzone, supported accept formats, and reachable text links. After adding a file, assert it appears in the queue on the same page; never show the action-choice heading. |
| 2 | Bild: Aktionen erscheinen, Komprimieren öffnet das Werkzeug mit der Datei ohne Upload | A selected image row shows its detected input type and a labeled `Ausgabe` selector with only available encoders. Choosing an output changes that row only; no upload occurs until `Konvertieren`. Keep image compression reachable as a secondary action without making it a required first step. |
| 3 | Bild: Konvertieren und Skalieren öffnen ihr Werkzeug mit der Datei | Start image conversion from the row/queue and assert the chosen output reaches the job request and the result/download stays on that row. Verify compression and scaling remain reachable as secondary actions and returning from one preserves the queue and each selection. |
| 4 | PDF: nur Komprimieren, das Werkzeug zeigt die Datei, kein Upload vor dem Start | The PDF stays visible with a `PDF komprimieren` action and a clear PDF label. It has no generic image/audio output selector and no fake PDF conversion. Assert no job request until the user explicitly starts compression. |
| 5 | Audio: nur Konvertieren, das Werkzeug zeigt die Datei, kein Upload vor dem Start | The WAV row offers only advertised MP3/WAV/FLAC/OGG outputs. Select MP3 and start; assert the row’s job options contain `format: mp3` and its download is associated with that same row. No pre-start upload. |
| 6 | Typ folgt der Signatur, nicht der Endung | Keep the PNG bytes named `foto.pdf`; assert the row identifies it as an image and offers image outputs, not PDF compression. |
| 7 | Unbekannter Typ: verständliche Meldung, keine Aktion außer Andere Dateien | Keep the unknown file in the queue with a file-specific explanation and remove control, but no `Ausgabe` selector or executable conversion. Add a valid neighbor and verify it remains usable; remove only the unknown row. |
| 8 | Gemischte Typen: Aktionen je Gruppe, das Werkzeug erhält nur die Dateien der Gruppe | Use separate rows for image, PDF, and unknown text. | 10 | Browser-Zurück führt vom Werkzeug zur Auswahl, Vor zurück zum Werkzeug | Replace phase-navigation assertions with URL/history stability: adding files, changing outputs, and starting conversion keep the page at `/` with no tool hash or route transition, and the same rows remain visible through processing/results. Do not expect Back/Forward to move among hidden queue phases; ordinary site navigation remains covered elsewhere. |
| 11 | Ablegen per Drag and Drop erkennt die Datei wie die Auswahl | Keep drag-and-drop, but compare its resulting row (name, detected type, and output choices) with picker selection. Assert the drop does not upload or navigate to another step. |
| 12 | Tastatur: Auswahl öffnen, Aktion wählen, zurück zur Dropzone | Use Enter/Space to open the picker, keyboard navigation to reach the row’s labeled output selector and choose a format, then reach and activate `Konvertieren` and a row remove button. Assert detection/processing is announced and removing the last row returns focus to the picker. Remove old focus assertions for the intermediate heading and action-choice buttons. |
| 13 | Datenschutz: nichts in Web Storage, IndexedDB oder Cache, keine fremden Hosts | Preserve the Web Storage, IndexedDB, Cache, external-host, and CSP audits. | 14 | axe: Auswahl, Erkennung und Werkzeug ohne Verstöße (dark, 390 px) | Keep all three scans: empty queue, populated/checking-or-ready queue with output selector, and post-start row status/result. Use the dark 390 px viewport; assert axe clean and no horizontal overflow. |
| 15 | axe: Auswahl, Erkennung und Werkzeug ohne Verstöße (dark, 1440 px) | Same states and assertions as #14 at dark 1440 px. Include a long filename or mixed rows so wrapping and per-row controls are exercised. |

## Coverage notes for the adaptation

- Keep the existing fixture builders and API doubles in `quickstart.spec.ts`; use `optionsOf(request)` from `e2e/audio-workspace.spec.ts` or the request-body checks in `e2e/direct-conversion.spec.ts` to prove the selected destination is sent. The route should return deterministic per-file success/error results for post-start accessibility and isolation assertions.
- `e2e/direct-conversion.spec.ts` already covers multiple audio targets, appending/removing rows without losing selections, image output payloads, mixed PDF/unknown rows, and returning from PDF compression. Preserve the uncovered QuickStart regression coverage above rather than duplicating those checks without a distinct purpose.
- Keep the spec’s explicit-start privacy guarantee and per-file result isolation even if the new direct-conversion file already tests the happy path. Preserve focused keyboard operations, all 4 axe combinations, and the no-horizontal-overflow checks.
